Telemetry in. Radio out.

Four moving parts, one calm voice in your ear.

01

Listen

ACC supplies car and session data through shared memory on Windows. An optional, listen-only Broadcasting API connection adds timing data; its live-game validation is still pending.

02

Think

A larger model reviews telemetry periodically and updates session memory: fuel, tyres, weather, damage and the pit plan.

03

Answer

A smaller model answers your question from the current memory without waiting for the next full analysis. Response time depends on your model and provider.

04

Speak

Piper speaks the reply. Telemetry-driven calls are suppressed while ACC is paused or in replay; you can still ask the engineer a question.

Choose your models.

Configure the background analysis and fast replies separately. Use a cloud provider or local Ollama, with Piper for speech.

Analysis

Background race analysis

Reviews the session and writes shared memory for the reply model. Current development evaluations use gpt-oss-120b through Ollama Cloud.

Replies

Driver questions and urgent replies

The smaller model reads session memory and phrases short replies. The current development setup uses gpt-oss-20b through Groq.

Voice

How it sounds

Piper generates speech locally. Choose the voice and output device in the app settings.

Provider choice, with trade-offs. Custom OpenAI-compatible endpoints are configurable. Speed and answer quality vary by model and hardware.

Current development.

Updated 18 September 2026. Recent ACC work is in the app code; a public release and live-session validation are still ahead.

Implemented

Fuel answers and pit-call filtering

Direct fuel questions now account for what the current tank can cover, even when a mandatory stop is owed. A separate guard filters unsolicited box calls when the available telemetry gives no reason to stop.

Beta · Off by default

Sector coaching

Compares sectors with your own best sectors in the session. This is sector-level feedback; corner-specific coaching needs further telemetry evidence.

Validation next

Live timing and race sessions

The broadcast listener, computed gaps and leaderboard are implemented. Protocol checks use synthetic packets; the next step is validation with a running ACC session and a fresh raw-data capture.

Testing now checks the answer, not just the topic. The 120-scenario evaluation checks verdicts, with additional multi-question and mistranscription modes. Replay and synthetic checks do not establish live-race reliability.

What the ACC engineer does.

Implemented capabilities in the development build. Beta features and remaining validation are called out above.

01

Voice radio and replies

Piper speech and Whisper voice input. Ask about fuel, tyres, penalties or mandatory stops while the analysis model works in the background.

02

Fuel and mandatory stops

Direct answers about fuel on the current tank, plus staged mandatory-stop deadline warnings. Pit-call filtering helps reduce unsupported calls to box.

03

Spin detection

Tracks spin incidents and repeat patterns. Traction-aid suggestions are gated on telemetry evidence, with unsupported suggestions filtered before speech.

04

Session memory

Background analysis maintains fuel, tyre, weather, damage and pit-plan context for the smaller reply model.

05

Tyre-set tracking

Tracks dry and wet sets used during the session. It does not claim how many sets remain: event allocations are not supplied by telemetry.

06

Dashboard and controls

Car telemetry, lap and sector timing, radio history and engineer settings in the local app. Optional LAN access puts the dashboard on a second device.

07

Radio preferences

Controls for dash readouts, quiet ticks, live timing and pit deadlines. Unprompted calls pause during menus and replays; direct questions still get answered.

08

Voice and provider settings

Select your microphone, speaker, language and AI providers. Use local or cloud transcription and separate models for analysis and replies.

Standing on other people's work.

airaceGP is a small project built on a lot of open work. This page names some of the people whose code, voices, translations and track maps make it possible. Full credits and notices are maintained in the app repository, which is currently private.

Voice

Piper by Michael Hansen and the Rhasspy project, and piper-plus by ayutaz. Voice datasets by Thorsten Mueller (German), Carlos Fonseca (Spanish), czyzi0 (Polish), the Nabu Casa voice-datasets team (Portuguese, Czech), the SIWIS project (French).

Speech recognition

Vosk by Alpha Cephei for the wake word. faster-whisper by SYSTRAN, riding on CTranslate2 by OpenNMT and SYSTRAN, with weights from OpenAI's Whisper. All MIT or Apache 2.0.

Translation

Argos Translate by Argos Open Technologies, with models trained on the OPUS parallel corpus collection curated by Joerg Tiedemann and the Helsinki-NLP group.

Track outlines

Traced from Wikimedia Commons maps by Will Pittenger, GabrielStella, HumanBodyPiloter5, Rumbin, Firkin, AlexJ, Ocdp, Sas1998, Dh16dh, Nasho3498, cBuckley, and ごひょううぺこ. CC0, CC BY 3.0, CC BY-SA 3.0 / 4.0.

Dashboard

Instrument Sans by the Instrument Sans Project Authors, Titillium Web by the Accademia di Belle Arti di Urbino, both SIL Open Font License 1.1. pywebview by Roman Sirokov, python-sounddevice by Matthias Geier, PortAudio by Ross Bencina and Phil Burk, NumPy contributors, ONNX Runtime by Microsoft.

Telemetry spec

ACC shared-memory documentation and Broadcasting SDK by Kunos Simulazioni. The existing F1 integration uses the EA/Codemasters UDP specification and packet layouts referenced from hotlaps.io (MIT).
